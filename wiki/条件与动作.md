# 条件与动作

## conditions

```yaml
conditions:
  - '%player_level%>=10<->&c等级不足，无法使用{id}'
  - '(%player_level%>=50)||("%player_has_permission_vip%"=="yes")<->&c需要 50 级或 VIP'
  - '%player_health%>10'
```

格式 `表达式<->失败消息`，失败消息可省略。全部满足才能使用。

条件不满足时，失败消息和 `messages.use-deny` 都会发送。只想显示自己写的失败消息时，把 `use-deny` 留空。

### 表达式语法

| 写法 | 说明 |
| --- | --- |
| `>=` `<=` `>` `<` `==` `!=` | 比较，每一段只能有一个 |
| `&&` `\|\|` | 并且、或者，`&&` 优先 |
| `( )` | 分组 |
| `+ - * / ^ %` | 四则运算，由 exp4j 计算 |
| `"文本"` | 字符串，只能用 `==` 和 `!=` |
| `true` `yes` `false` `no` | 布尔字面量 |
| 单独的数学式 | 结果不为 0 时成立 |

两侧有任意一边不是数字时按字符串比较。占位符可能返回文本时要加引号。

### 占位符

`%xxx%` 由 PlaceholderAPI 解析。`{id}` 是药水节点，`{split}` 是分隔符。失败消息里 `&` 转颜色符号，`%id%` 也可用。

### 判定失败

表达式无法解析时按不满足处理，后台输出是哪个药水的哪条表达式。常见原因：没装对应的 PlaceholderAPI 扩展，占位符原样留在表达式里。

## actions

```yaml
actions:
  success:
    - '[msg]&a使用了{id}'
    - '[console]give %player_name% diamond 1'
  end:
    - '[msg]&c{id}结束了'
  tick:
    20:
      - '[actionbar]&a生效中'
```

| 阶段 | 时机 |
| --- | --- |
| `success` | 使用成功后 |
| `end` | 到期、被移除、覆盖使用、`optional.death`、`optional.quit` 时。离线到期时在下次进服补执行（可关闭） |
| `tick` | 按 tick 间隔周期执行，键是间隔 |

玩家正常下线和关服不算结束，不执行 `end`。

### 前缀

| 前缀 | 格式 | 说明 |
| --- | --- | --- |
| 无 | `指令` | 以玩家身份执行，开头的 `/` 可有可无 |
| `[console]` | `指令` | 控制台执行 |
| `[op]` | `指令` | 临时给 OP 执行，执行完立即恢复 |
| `[msg]` | `文本` | 发消息 |
| `[title]` | `大标题<->小标题<->淡入<->停留<->淡出` | 后三段单位 tick，必须是整数 |
| `[actionbar]` | `文本` | 物品栏上方文字 |
| `[bossbar]` | `标题<->颜色<->样式<->秒数` | 秒数为 0 或负数时显示到下线 |

- 动作里的药水节点写 `{id}`，不是 `%id%`。
- `&` 在加载时转成颜色符号。指令参数里真的需要 `&` 字符时要注意。
- 单条动作失败只记录日志，不影响后续动作，也不影响物品扣除。

### [op] 的风险

`[op]` 执行期间玩家确实是 OP。被执行的指令如果排了延迟任务或触发别的逻辑，可能在 OP 窗口内以高权限运行。优先用 `[console]`。

### 变量安全

条件和动作里的占位符值如果来自玩家可控的文本（昵称、物品名），可能带入引号或指令内容。不要把这类占位符拼进 `[console]`、`[op]` 指令和条件表达式。
