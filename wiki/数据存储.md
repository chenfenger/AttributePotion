# 数据存储

## 配置

SQLite（默认）：

```yaml
mysql:
  enable: false
  file_name: AttributePotion   # 生成 plugins/AttributePotion/AttributePotion.db
```

MySQL：

```yaml
mysql:
  enable: true
  host: localhost
  port: 3306
  username: root
  password: root
  file_name: attributepotion   # 数据库名
  table_name: data
  driver: 'com.mysql.jdbc.Driver'
  jdbc: '?useSSL=false&useUnicode=true&characterEncoding=utf8'
  pool:
    maximum-pool-size: 10
    minimum-idle: 2
    connection-timeout: 30000
    max-lifetime: 1800000
    idle-timeout: 30000
```

旧配置节 `MySQL.enable`、`MySQL.fileName`、`MySQL.tableName` 等也能读取。

## 保存什么

每个玩家一行 JSON，存在 `<table_name>_profile` 表：激活中的药水（节点、开始时间、结束时间、已应用的属性）、药水冷却、药水组冷却。

新建的 MySQL 表使用 `utf8mb4`。已有的表如果是 latin1，中文药水节点会存成问号，需要手动转换：

```sql
ALTER TABLE data_profile CONVERT TO CHARACTER SET utf8mb4;
```

## 什么时候读写

所有读写在同一条后台线程按顺序执行，退出时的保存一定先于再次登录的读取。

| 时机 | 行为 |
| --- | --- |
| 进服 | 读取。读到后立刻合并冷却并允许使用药水，`load-delay` 后恢复激活中的药水 |
| 下线 | 先结算到期药水，处理 `optional.quit`，然后保存并撤销属性 |
| 定时 | 每 `auto-save-interval` 秒保存在线玩家 |
| 关服、卸载插件 | 等后台队列写完，同步保存所有在线玩家，撤销属性。不执行 `end` 动作 |
| 热加载插件 | 主动读取已在线玩家的数据 |

## 异常情况

| 情况 | 行为 |
| --- | --- |
| 启动时连不上数据库 | 插件继续运行，药水可用，本次运行不读不写，后台输出错误 |
| 读取某玩家失败或 JSON 损坏 | 该玩家本次在线期间可以使用药水，但**不写回**，存档保持原样 |
| 数据还没读完时使用药水 | 拒绝，发送 `data-loading` 消息 |
| 读取期间玩家下线 | 不写回，存档保持原样 |
| 恢复等待期间玩家下线 | 待恢复的药水一并保存，不会丢失 |
| 药水配置被删除 | 该药水不再恢复属性和效果，到期后清除，不执行 `end`。永久药水会一直留在存档里，配置加回来后下次进服继续生效 |

## 时间

冷却和药水结束时间都是绝对时间戳，下线和关服期间继续流逝。

## 旧数据兼容

新表没有该玩家的记录时，会读旧表 `<table_name>`（激活药水）和 `time_record`（冷却），下次保存写入新表。旧表不会被修改或删除。

SQLite 没有配置 `file_name`、且插件目录有旧版 `database.db` 时，继续使用旧文件。
